# 裁剪边界响应引导的火电厂完整性恢复推理

这是冻结 DSQC+RBA 检测器后的独立推理实验模块。入口为 `裁剪响应自适应推理.py`，所有新增代码位于本目录。默认显式加载 `my_improve/dfine_hgnetv2_m_dsqc_rba.yml`，复用仓库已有脚本中的模型加载、预处理和预览函数。

**实现状态：**策略、栅格适配、结果导出、对照选项和离线评价已实现。策略/评价的 40 项测试及真实栅格读写配合替身检测器的 5 项集成测试通过；尚未使用实际 DSQC+RBA 权重验证精度和速度收益。默认阈值是实验起点，需要在独立验证区域确定。

## 思路与实现边界

火电厂主体可能在一个窗口内只露出部分结构；局部框也可能有很高的置信度。本实现利用同一目标在不同裁剪位置下的响应，选择需要补充的上下文，并保留完整观测。

1. 全景执行固定重叠滑窗初检，记录每个框的原图像素坐标及来源窗口。
2. 在同尺度、不同位置的真实裁剪之间，对每一条边计算 `r = 预测框全局边界位移 / 裁剪窗口边界位移`。人工裁剪边附近出现约为 1 的响应，作为目标可能仍被裁断的证据；安全边距内的边界在不同裁剪下保持稳定，作为可靠性证据。未移动的轴不计算该比值，不同尺度也不直接比较该比值。
3. 根据风险方向平移窗口；出现边界跟随或相对两边同时贴边时扩大源窗口。较大源窗口仍缩放到固定的模型输入尺寸，避免改变检测网络。
4. 完整性确认需要不同裁剪的稳定观测。融合以已有可靠完整框为依据；只有在完整框投回片段原窗口后能够唯一解释片段时，才吸收截断片段。匹配始终参考初始锚点，并检查同窗共现的独立目标，减少相邻厂区误并。
5. 每个目标假设和整景均设补推上限；相同 `(x, y, size)` 的窗口复用缓存。未找到匹配、发生歧义或预算耗尽时保留已有结果并标记状态。

这里的 `stable/recovered` 是预测之间的几何一致性状态，不代表经过真值确认，也不是对实际厂区完整性的保证。真实影像外边界没有可恢复的上下文；补零不会被当成有效观测。初检完全漏掉且未被其他目标补推窗口覆盖的厂区，仍可能漏检。

论文中可检验的核心假设是：**裁剪干预后的边界响应能否比静态贴边规则更有效地指导补推，并改善完整框定位。**重叠滑窗、目标居中、扩大窗口和普通融合本身不作为新增贡献。当前实现也没有引入设备级知识图谱、额外模型训练或学习式调度器。

## 运行

在入口顶部的“用户配置区”填写 `CHECKPOINT`，核对 `INPUT_TIF`。权重需对应实际 DSQC+RBA 配置；保留严格参数匹配，不会自动切换到其他改进模式。`my_improve/settings.py` 当前开关不用于决定本入口的模型。

从仓库根目录执行：

```powershell
conda activate dfine
python "myscript\推理策略改进\裁剪响应自适应推理.py"
```

也可直接通过参数提供路径，下面的路径需要替换为实际文件：

```powershell
python "myscript\推理策略改进\裁剪响应自适应推理.py" --input "影像.tif" --checkpoint "DSQC_RBA权重.pth" --strategy response
```

Shapefile 由入口顶部两个参数控制，无需输入命令行开关：

```python
WRITE_SHP = True                  # True 输出 SHP；False 不输出 SHP
SHP_FILENAME = "predictions.shp" # 可改为 "准格尔召镇检测结果.shp"
```

文件名必须保留 `.shp` 后缀且不能包含目录。输出坐标系与原影像一致，可直接在 ArcMap 中加载。一个 Shapefile 还会生成同名的 `.shx`、`.dbf`、`.prj` 等配套文件，复制或移动时要把它们放在一起。`--help` 查看全部参数；`--dry-run` 检查配置和路径，不加载模型或影像，也不创建结果目录。`--dry-run` 即使发现未填权重也会正常退出，具体看输出的 `path_exists`。

输入要求：至少三个波段，前三个波段依次为 uint8 RGB，辐射范围与训练影像一致，具有正确 CRS。读取时综合三个波段的有效掩膜和黑像素阈值。其他位深或波段顺序需预先转换。运行沿用现有 `dfine` 环境，无需新增训练依赖。

默认在本目录 `results/时间戳/` 创建结果。可通过 `--output` 指定新目录，非空目录会被拒绝，以便保留不同实验的原始输出。

## 关键参数

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `--base-size` / `--stride` | 512 / 256 | 初检源窗口与步长，单位为原图像素 |
| `--scales` | 512 768 1024 | 允许的源窗口尺寸，严格递增且从基础尺寸开始 |
| `--model-input-size` | 512 | 各种源窗口统一缩放后的网络输入尺寸 |
| `--shift-pixels` | 64 | 基础尺度的探测位移，随当前源窗口尺度同比调整 |
| `--max-refines` | 3 | 每个目标假设最多请求的补充视图数，包含缓存命中 |
| `--global-budget` | 1000 | 整景最多新增的补推窗口数，包括读后发现无效的窗口 |
| `--candidate-confidence` | 0.05 | 保存和关联的候选分数下限，也限制 AP 可达到的召回 |
| `--confidence` | 0.2 | 最终空间文件/预览导出及固定阈值 P/R/F1 的分数下限 |
| `--topk` | 50 | 每个视图进入策略的最大候选数，所有方法保持一致 |
| `--batch-size` | 6 | 基础窗口前向的批大小；自适应补推逐窗执行 |
| `--grid-offset X Y` | 0 0 | 改变初检内部格网起点，保留边缘窗口保证覆盖 |

更多几何阈值位于 `strategy.py` 的 `StrategyConfig`，可用 `--strategy-config 参数.json` 覆盖，例如：

```json
{
  "policy": "response",
  "edge_margin_ratio": 0.0625,
  "stable_tolerance": 0.025,
  "response_min": 0.6,
  "response_max": 1.4,
  "refine_min_confidence": 0.15,
  "stable_confidence": 0.5,
  "min_object_pixels": 24,
  "max_refines_per_target": 5
}
```

显式命令行参数优先于 JSON。使用 JSON 时，未写入 JSON 的策略字段来自 `StrategyConfig`，而不是入口顶部的自定义常量；最终有效参数以 `run.json` 为准。

`stable_tolerance` 按目标宽或高归一化；`edge_margin_ratio` 按当前源窗口大小计算。扩大窗口时还检查目标短边缩放到模型输入后至少为 `min_object_pixels`，限制上下文扩大带来的目标缩小。

预算按**目标假设**计数，同一真实厂区的不同片段仍可能初始化多个假设。整景预算是新增窗口上限，不等同于 CUDA 前向调用数；一个批次可包含多个基础窗口，无效补推窗口则不执行模型。以 `backend_stats.model_view_count` 和计时统计实际计算成本。

## 对照和消融

保持相同权重、影像、输入尺寸、候选阈值、top-k 和后处理阈值，分别运行并使用不同输出目录：

| 选项 | 行为与用途 |
| --- | --- |
| `--strategy overlap` | 基础重叠滑窗 + 窗内去重 + 全局 NMS，无自适应补推 |
| `--strategy static` | 静态贴边判断，居中/扩域；使用相同的关联、稳定性停止和融合逻辑 |
| `--strategy fixed` | 固定选取第二个允许尺度，以初始框中心和预设偏移取上下文；使用相同停止条件 |
| `--strategy random` | 在允许尺度和局部位置内随机提出补推窗口，随机种子由 `--seed` 固定 |
| `--strategy response` | 裁剪响应引导的方向性补推和扩域，主方法 |
| `--strategy response --no-side-fusion` | 保留调度，改为已关联观测的普通置信度加权整框平均，检验可靠完整观测约束的作用 |
| `--strategy response --max-refines 0` | 只使用基础观测进行关联和可靠性判断，检查新增补推的贡献 |

`static/fixed/random` 是本实现内部的受控调度对照，并非同名论文算法的完整复现。它们共享稳定性停止条件，因此相同预算上限不代表实际开销相同；正式比较应同时报告实际模型视图数和耗时，并通过预算扫描绘制精度—成本曲线。

建议先在验证区域比较每目标预算 `1/3/5`，并检查源窗口 `512/768/1024` 是否适合影像 GSD 和厂区大小，再固定设置测试。格网敏感性可比较 `(0,0)`、`(80,120)`、`(128,128)`，随机对照需多种子重复。改变格网时评价分层的参考格网始终固定 `(0,0)`，以保持各方法目标分组一致。

## 输出与评价

| 文件 | 内容 |
| --- | --- |
| `run.json` | 有效参数、权重和实现摘要、模型/影像信息、运行状态、视图数、缓存统计及计时 |
| `effective_model_config.json` | 展开 include 后的模型配置，方便核对 DSQC+RBA 和输入尺寸 |
| `predictions.geojson` | 达到最终置信度的检测，标准 WGS84 经纬度多边形 |
| `predictions.csv` | 原图像素 xyxy、分数、目标状态、支持窗口数及可信边标记 |
| 自定义名称的 `.shp` / `predictions.gpkg` | SHP 由顶部 `WRITE_SHP` 和 `SHP_FILENAME` 控制；GPKG 使用 `--write-gpkg`，坐标系均与输入影像一致 |
| `preview.png` | 整景缩略检测图，`--no-preview` 可关闭 |
| `candidates.json` | 最终置信度筛选前、融合/NMS 后的预测，以及各来源窗口的候选观测；均为原图像素坐标 |
| `events.jsonl` | 每次补推的原因、窗口、缓存命中、关联结果和边界响应 |
| `targets.json` | 每个初始目标假设的支持观测、停止原因、片段吸收关系及是否保留 |
| `windows.json` | 尝试读取的窗口、有效比例及是否跳过 |
| `metrics.json` / `ground_truths_pixel.json` | 指定 `--gt` 时生成的整景评价及转换后的像素真值 |

主要状态包括 `stable`（基础观测已满足稳定性规则）、`recovered`（请求补充视图后满足规则）、`image_boundary`、`budget_exhausted`、`scale_limit`、`ambiguous`、`not_found` 和 `unverified`。低置信度候选不会因缺少稳定性证据被直接丢弃；是否对外导出仍由最终置信度决定。

真值只在全部推理和结果导出之后读取，不参与目标选择、窗口调度或提前停止。使用 `--gt 标签.shp`，或提供 GPKG/GeoJSON；检测标签需为 Polygon/MultiPolygon，每个要素对应一个厂区检测目标。GeoJSON 未声明 CRS 时按 WGS84 解释。像素真值也可明确写成：

```json
{
  "coordinate_space": "pixel",
  "ground_truths": [
    {"box": [400, 150, 850, 440], "class_id": 1, "plant_id": "plant_001"}
  ]
}
```

评价包含 AP50、AP75、AP50:95、固定置信度 P/R/F1、重复框数、TP 的逐边归一化定位误差，以及超尺寸、格网位置截断、整景外边界等分层召回。标签应遵循当前数据集的厂区标注口径；不要把设备框或多个相邻工厂的并集当作同一类完整厂区真值。

AP 使用传入的低阈值融合结果，不使用最终展示置信度提前截断。本评价采用整景单类别 101 点插值，没有实现 COCO 的 maxDets、ignore、crowd 和面积分组，指标命名为 `scene_single_class_*`，**不能直接写成官方 COCO AP**。TP 边界误差不涵盖漏检目标，应与召回一起报告。

若有效评价面积已独立计算，可传 `--valid-area-km2` 输出每平方公里误检数；未提供时该指标为 `null`。程序不把地理坐标中的角度面积当作平方公里，也不默认整景矩形均为有效评价区域。

## 检查与后续实验

纯策略和评价测试只需标准 Python；栅格集成测试需要现有 `dfine` 环境，缺少依赖时会跳过：

```powershell
conda activate dfine
python -B -m unittest discover -s "myscript\推理策略改进\tests" -v
python "myscript\推理策略改进\裁剪响应自适应推理.py" --dry-run
```

集成测试使用临时小幅 GeoTIFF 和替身检测器验证读取、坐标转换、输出与评价流程，不运行真实权重。正式实验建议先选一个含跨窗大厂区、相邻厂区和易混工业背景的小区域，检查 `events.jsonl` 与实际框是否符合预期，再开展独立区域的整景对比。当前代码完成的是可复现实验入口，论文创新有效性仍需这些真实数据实验支持。
